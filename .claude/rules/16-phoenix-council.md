# قانون ۱۶ — شورای ققنوس: ۱۲ مراقب زودیاک و حکم وزنی ققنوس (دستور حمید، ۲ سپتامبر شب)

حمید: «۱۲ مراقب ققنوس را نام‌گذاری کن به زودیاک… دستورات لازم برای
استراتژی تخصصی را در اختیارشان قرار بده؛ و بعد مشاهدهٔ سیگنال و اعلام
رأی ققنوس که تو هستی، بر اساس وزن رأی می‌دهی که سیگنال چگونه باشد.»

**ققنوس = ایجنت اصلی (E00).** پیاده‌سازی قطعی: `hamid/phoenix.py`.
هیچ مدل زبانی روی سیگنال صدا زده نمی‌شود (قانون ۰۶)؛ هر مراقب یک تابع
پایتونی است که فقط میدان تخصص خودش را می‌خواند.

## دوازده مراقب و دستور تخصصی هر کدام

ترتیب همان ترتیب تحلیل حمید است (قانون ۰۰): بستر → ساختار → مکان →
نقدینگی → کندل/اجرا → ریسک → حافظه → دیدگاه → دادهٔ سالم.

| مراقب | تخصص | دستور (خلاصه) |
|---|---|---|
| ♏ عقرب | دامیننس تتر/بیت‌کوین | ۴س بعد ۱س؛ USDT.D صعودی = بازار نزولی؛ شاهدِ هم‌ترازِ تایم‌فریم حرف اول؛ کهنه‌تر از ۹۰د = ممتنع |
| ♊ جوزا | بستر بیت‌کوین، لید-لگ | COUPLED بدون همراهی BTC حق ورود ندارد؛ INDEPENDENT = وزن رأی نصف |
| ♉ ثور | روند ۴س/۱س | هر دو هم‌جهت = تأیید قوی؛ یکی خلاف = ضعیف؛ هر دو خلاف = مخالف (قانون ۲) |
| ♈ حمل | ایمپالس، BOS، پولبک | ضربهٔ بلاک ≥۶؛ CHoCH داخل پولبک = تله (قانون ۵)؛ پولبک اول = مخالف |
| ♌ اسد | اردر بلاک/FVG | تعریف حمید از OB؛ تازه = تأیید؛ OB مخالف جلوی راه یا ۳ بار برگشت‌خورده = مخالف |
| ♋ سرطان | نقدینگی و سوییپ | سوییپ اخیر = تأیید؛ آهن‌ربای نقدینگی هم‌جهت تارگت = تأیید، خلاف = مخالف |
| ♓ حوت | کندل و کیفیت ورود | الگو تأیید ثانویه است نه ماشه؛ کیفیت ≥۷۰ + الگوی هم‌جهت = تأیید؛ کیفیت <۵۰ = مخالف ضعیف |
| ♎ میزان | ریسک، کارمزد، RR | کارمزد ≥۰.۲۵R = دام اسکالپ، مخالف؛ RR ≥۱.۸ و کارمزد ≤۰.۱۵R = تأیید |
| ♑ جدی | حافظه و کارنامه | n≥۱۲ با انتظار مثبت = تأیید؛ <−۰.۳R = مخالف؛ نمونهٔ کم = ممتنع |
| ♍ سنبله | کیفیت داده، هم‌زمانی | کندل از بازار اجرا (بیت‌یونیکس پرپ) = تأیید؛ >۱.۵٪ دور از ورود = مخالف |
| ♐ قوس | کلان و خبر (دیدگاه) | اجماع خبری هم‌جهت/خلاف = رأی ضعیف؛ سهم با دلو ≤۵٪ (قانون ۱۵) |
| ♒ دلو | جمعیت و فومو (دیدگاه) | شاهد فومو = تأیید ضعیف؛ داغی ≥۸۰ در لانگ = خطر تله؛ سهم با قوس ≤۵٪ (قانون ۱۱) |

متن کامل دستور هر مراقب در `GUARDIANS` داخل `hamid/phoenix.py` و روی
`signals/phoenix.json` است.

## رأی، وزن، حکم

- رأی هر مراقب عددی در [−۱, +۱] است (علامت = جهت، بزرگی = اطمینان) با
  دلیل یک‌خطی، یا **ممتنع** وقتی دادهٔ تخصصش نیست (قانون ۱).
- وزن پایهٔ همه ۱؛ قوس و دلو ۰.۳ با سقف مشترک ۵٪ کل رأی. وزن فقط با
  کارنامهٔ خودِ همان مراقب روی دفتر بسته جابه‌جا می‌شود: باند ±۰.۱۵ تا
  وقتی CI ویلسون از ۵۰٪ رد نکرده، ±۰.۴۰ بعد از آن؛ زیر ۱۲ نمونه هیچ
  حرکتی. هیچ مراقبی وتو ندارد و هیچ وزنی صفر نمی‌شود.
- حکم ققنوس = میانگین وزنی رأی‌های غیرممتنع:

| امتیاز | حکم | پیشنهاد اندازه |
|---|---|---|
| ≥ +۰.۴۵ | تأیید قوی | سایز کامل |
| ≥ +۰.۱۵ | تأیید | سایز نصف |
| (−۰.۱۵, +۰.۱۵) | بی‌نظر | فقط پیپر / نظارت |
| ≤ −۰.۱۵ | مخالف | نرو |

  با کمتر از ۴ رأی‌دهنده: «بی‌نظر — شواهد کم».

## کجا دیده می‌شود

- کپشن هر سیگنال: خط «🔥 ققنوس: حکم (موافق · مخالف · ممتنع، امتیاز) —
  پیشنهاد اندازه» + قوی‌ترین دلیل هر طرف.
- دفتر پیپر: `phoenix_score` / `phoenix_label` / `phoenix_votes` روی هر
  ردیف؛ دو شرط شبانه «ققنوس تأیید (≥+۰.۱۵)» و «ققنوس مخالف (≤−۰.۱۵)».
- `brain/phoenix/verdicts.jsonl` (append-only) · `brain/phoenix/scores.json`
  (کارنامه) · `signals/phoenix.json` (تابلو، ردیف قرارداد E00) · کارت
  «شورای ققنوس» در پنل.
- چرخهٔ حمید هر نوبت `hamid.phoenix --score --write` را می‌زند.

## مرز (قانون ۰۳/۱۲ — تغییرناپذیر بی‌دستور صریح حمید)

حکم ققنوس **مشاوره‌ای** است: هیچ سیگنالی را حذف نمی‌کند و هیچ عددی
(ورود/استاپ/تارگت/اهرم) را عوض نمی‌کند. «سیگنال چگونه باشد» یعنی
برچسب اعتماد و پیشنهاد اندازه روی همان سیگنال. ورود حکم به دروازه یا
سایز خودکار فقط وقتی ماشین شبانه CI بالای صفر بدهد و حمید تأیید کند.

محافظ: `hamid/test_phoenix.py` در دروازهٔ هر دو زنجیره.
